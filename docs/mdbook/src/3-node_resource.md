# Node Resource

Node resources look something like this:

```yaml
{{#include z-node.yaml}}
```

## Explanation

Dissecting this resource, you can see several important fields:

- `spec.clusterRef`: reference to the Cluster resource this Node belongs to
- `spec.role`: role of the node (controlplane or worker)
- `spec.patches`: patches to apply to the base configuration from the Cluster resource, or on top of other `spec.patchRefs`
- `status.effectiveConfig`: the full Talos configuration that will be applied to the node, generated by the operator
- `status.kubernetesVersions`: the versions of Kubernetes components currently running on the node
- `status.operationStatus`: the last operation performed on the node, and its status
  - This one is particularly important, as it shows you exactly what the operator is currently doing with the node, or did most recently.

> [!NOTE]
> Secrets are intentionally omitted from `status.effectiveConfig` for security reasons. The applied configuration will still contain the secrets when sent to the node.

### `status.conditions`

The `status.conditions` field contains a list of conditions representing the current state of the Node resource.

- `Ready`: Indicates whether the node is successfully provisioned and operational. **Does not** indicate if Kubernetes is ready.
- `Provisioned`: Indicates whether the node has been successfully provisioned with the desired configuration.
- `ConfigInSync`: Indicates whether the node's configuration is in sync with the desired configuration specified in the Node resource. If `False`, a configuration apply operation will bring it in sync.
- `KubernetesReady`: Indicates whether the Kubernetes Node is in a ready state. Might be false if CNIs or other components are not up or deployed.
- `KubernetesNeedsUpdates`: Indicates whether the Kubernetes components on the node need to be updated to match the cluster's desired Kubernetes version.
