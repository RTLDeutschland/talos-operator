# Resetting a Node

To safely remove and erase a Node, you can simply delete the corresponding `nodes.talos.rtl.de` resource from Kubernetes.

This has the same effect as patching the Node with the following, while also deleting the resource from Kubernetes:

```yaml
operation:
  type: Reset
```

or the [kubectl-talos](./5.1-kubectl_plugin.md) equivalent, `kubectl talos reset NODE`.

[Refer to the Talos manual for more information](https://docs.siderolabs.com/talos/v1.11/configure-your-talos-cluster/lifecycle-management/resetting-a-machine) as to what this does on the Talos side, but safe to say:

> [!CAUTION]
> ALL DATA ON THE NODE WILL BE LOST.
>
> This includes everything on the system disk, including the OS, **as well as user volumes**.

## Cloud resets

As noted in the Talos manual, this will also wipe your system partition, resulting in an unbootable machine. You may instead want to consider:

```yaml
operation:
  type: Reset
  reset:
    systemLabelsToWipe:
      - STATE
      - EPHEMERAL
    reboot: true
```

or the kubectl-talos equivalent, `kubectl talos reset --cloud-reset --reboot NODE`.

This will "only" wipe `/var`, etcd data, the system configuration and user data, resetting a node back into maintenance mode (`reboot: true`), ready to be provisioned again. The operator is smart enough to detect this and will set the `Provisioned` condition back to `False`, allowing you to reprovision the node again. If you wish to avoid wiping user data (user-defined volumes, **not** EPHEMERAL), set `mode: system-disk` or `--wipe-mode=system-disk`.
