# Kubernetes upgrades

A cluster may be upgraded to a new Kubernetes version by patching the Cluster resource with the following:

```json
{"operation": {"type": "KubernetesUpgrade"}}
```

This will generate a plan in `status.subOperations`, showing all the steps that the cluster reconciler will take to update every component and every node of the cluster.

The reconciler will then proceed to execute this plan. Any failure will fail the cluster operation, and freeze in the state it was in when the failure occurred. The plan may be resumed by re-patching the same operation again. Re-issued Kubernetes component upgrade operations will just be skipped if the desired state is already reached.

## Storage Considerations

If your cluster uses [Longhorn](https://longhorn.io) or another storage solution with significant volume eviction times, consider increasing `spec.options.drainTimeout` to avoid timeouts during the node drain phase. See the [Cluster Resource documentation](./4-cluster_resource.md#specoptionsdraintimeout) for details.
