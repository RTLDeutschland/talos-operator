# Unattended configuration and Kubernetes upgrades

The Cluster reconciler can be configured to automatically apply configuration changes and Kubernetes upgrades inside a specified maintenance window.

To do this, set the `spec.options.maintenanceWindow` field on the Cluster resource:

```yaml
spec:
  options:
    maintenanceWindow:
      enabled: true
      cron: "0 2 * * 0" # every Sunday at 2am
      #duration: "2h"    # optional, defaults to 1 hour
```

The next maintenance window will then be visible as `status.nextMaintenanceWindow`.

## Logic

When the operator detects a node with condition `ConfigInSync` or `KubernetesInSync` as `False`, the appropriate cluster-side Condition is updated to indicate that work needs to be done (`ClusterNodesInSync` or `ClusterNodesKubernetesUpToDate`).

Based on these two conditions, and only if the last operation on the cluster was successful[^fail], the decision is made to initiate a `RollingApply` or `KubernetesUpgrade` cluster operation, possibly in sequence.

Running cluster operations may exceed the maintenance window duration, but will never start outside of it.

Finally, if anything fails, the automation stops and the error must be cleared by hand. This means that in the worst-case condition, the automation will only ever disrupt a single node.

[^fail]: Human-initiated or otherwise.

## Permanent maintenance windows

It may be desirable to have a permanent maintenance window, for example in dev or lab environments.

To achieve this, simply set a cron expression that is always true: `0 * * * *` (assuming the default 1-hour duration).
