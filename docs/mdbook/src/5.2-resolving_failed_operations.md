# Resolving a failed operation

In all cases of operation failure, to resolve a failed operation you can simply trigger another operation on the same resource. This will clear the previous operation and allow you to proceed with the new operation. For example, if an apply operation fails, you can simply run another apply operation to clear the failed state and proceed with the new apply.

## Node drain failures

[Unlike talosctl](https://github.com/siderolabs/talos/issues/9882), the operator tries to run a safer drain by default, eviction enabled. This means that if the drain fails, the operator will not proceed with the operation and will instead mark the operation as "drain failed".

To work around this, look at your cluster's Pod Disruption Budgets to make sure you're not trying to drain more nodes than your PDBs allow. If you need to, you can temporarily remove or relax your PDBs to allow the drain to succeed. Once the drain succeeds, you can reapply your PDBs as needed.

```bash
$ kubectl talos kubectl -n your-cluster-namespace your-cluster -- get -A poddisruptionbudgets
```

Alternatively, if you don't care about draining the node safely, there is the `unsafe` flag you can pass to the operation:

```yaml
operation:
  type: Apply
  options:
    unsafe: true
```
